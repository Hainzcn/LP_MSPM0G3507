# 项目 自平衡瞄准小车

## 任务

设计一个两轮自平衡小车，小车能够沿一条圆形黑线（圆环）稳定行进。在圆环的中心位置竖直固定一个矿泉水瓶，瓶身贴有白色UV感光纸张。小车车身安装一个激光发射器（激光功率符合安全标准），要求小车在绕圆环行进过程中，激光点始终照射在感光纸张上，且感光纸上激光点的上下波动幅度尽可能小。

## 要求

1. 基本要求
  1. 将小车放置在起跑线，一键启动后能够立刻实现稳定站立 3 秒，前后移动幅度不超过10cm；
  2. 能够直立沿圆环黑线稳定行进完整一周（360°），行进过程中不得脱离黑线超过 2 秒；
  3. 完成一周后，小车回到出发点附近，稳定站立并发出声、光提示；
  4. 在整个行进过程中，小车上的激光点必须始终照射在矿泉水瓶的白色UV感光纸上（允许短暂抖动，但离开纸张时间累计不超过2 秒）。
2. 发挥部分
  1. 小车能够沿圆环连续行进两周，且激光点始终保持在感光纸范围内；
  2. 在行进过程中，感光纸上激光点的上下波动幅度（即激光点中心与感光纸几何中心的垂直距离最大值）≤2cm；
  3. 小车发车时能够实现自主原地起立（即一键启动前小车可任意倾倒，启动后不可用外力搀扶）；
  4. 在完成上述任务的前提下，行进速度越快越好（按完整一周的时间计）。

## 说明

1. 小车底盘可附加倾倒保护装置，但车轮落地时，车身不可依靠保护装置实现直立，小车可自由倾倒。倾倒时，车身垂直轴线与地面水平线夹角θ（见附录示意图）不大于60 度，要求在车身标记中轴线，方便检查；
2. 要求使用 TI（推荐 M0 系列）或瑞萨的主控芯片作为小车的核心控制器件。若使用带有其他微控制器的摄像头模块应只用来进行图像识别与分类功能，摄像头模块拆除后仍可实现直立。
3. 圆环黑线内径约80cm，黑线宽度约 1.8cm。圆环中心放置一个普通矿泉水瓶（高度约 23cm），瓶身用白色UV 感光纸包裹（纸张包裹瓶身后，整体高度不可超过25cm）。激光点应照射在纸张范围内，纸张上可观察光斑位置。激光发射器波长405nm，功率≤5mW（安全等级Class3R以内）。激光器由小车独立供电，不得使用外部对准辅助。
4. 小车底盘仅包含如附图所示的电机、车轮和一块铝合金支撑板。

# 项目规划

1. 主控板使用安装 MSPM0G3507 芯片的 TI 开发板，视觉模块使用 K230 模块（CanMV）。
2. 使用 MPU6050 姿态传感器完成姿态解算与简单惯性导航。
  因题目未要求，可使用自带四元数计算的十轴姿态传感器 ATK-MS901M ，针对该传感器的数据解析与惯性导航ins管线已相对成熟，但其中十五阶卡尔曼滤波极需性能，恐 MSPM0G3507 芯片无法胜任惯性导航解算任务。
3. 二维MG90S舵机云台 控制激光俯仰与360旋转。
  尝试自制双自由度云台，完成驱动编写封装与机械设计有一定挑战性。
4. 使用 TB6612 做电机驱动模块。
5. 待补充。

# 执行计划

1. 先规划 MSPM0G3507 引脚并完成定义，需连接的包括姿态传感器、双路电机驱动模块、舵机模块、视觉模块等。若有盈余则配置蓝牙串口以便于调试。
2. 连接 MPU6050 或 MS901M 姿态传感器，完成数据解析和串口转发。
3. 连接 TB6612 电机驱动模块，编写电机驱动，初步完成电机转动调试。
4. 根据姿态传感器信息完成平衡程序编写。
  - *是否可以结合轮径、质量、重心位置等先验数据辅助平衡算法？*
5. 待调试至小车可稳定平衡后，完成基础运动（前进、后退与转向）方案、自立方案规划。
6. K230 模块实装双摄像头，一个用于捕捉激光落点，另一用于完成路径解算与预测。该模块与主控见通信协议需设计，路径规划与基础运动模块联动需设计。
  - 注：对于双轮平衡小车的视觉循迹方案有待商榷，因小车不可保证地有轻微抖动，且前进后退时的俯仰变化会导致视觉画面透视变化，故可能需要结合传感器俯仰信息才能完成路径解算。  
  - *是否可使用铅锤法配合轴承打造机械水平摄像头基座，减少抖动与画面变化，但该稳定系统的阻尼调教不应该是该项目重心*
7. 云台对于灵敏度与精度要求较高，舵机选型尚未规划。为解放 MSPM0G3507 主控，防止中断任务阻塞，可能需要独立 MCU 边缘控制。故云台是否需要自制有待商榷。
8. 待补充。

## 一、总体评价

题目本质上是一个 **多回路、强耦合、带载体扰动隔离需求** 的小型移动机器人项目，难度高于一般"循迹平衡车"。难点不在"会平衡 + 会循迹"，而在 **平衡车不可避免的车身俯仰抖动 → 直接耦合到激光指向误差**。
你目前的规划给出了主要的硬件骨架与软件迭代顺序，方向是对的；但 **控制架构、传感反馈、子系统耦合关系、任务调度与里程碑划分** 几个层面尚未展开，存在若干关键缺漏，下文逐项展开。

## 二、对任务的关键量化分析（开工前必读）

请把这组数字钉在脑子里，它决定了你能不能拿到发挥分：

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 圆环内径 | 80 cm | 即内半径 R≈40 cm |
| 车体到瓶心水平距离 | 约 40.9 cm | 车循迹中心 + 半个线宽 |
| 感光纸中心高度 | ≈ 12.5 cm | 瓶高 23 cm，纸高 ≤25 cm |
| **发挥项波动容差** | **≤ 2 cm（垂直）** | 题目硬指标 |
| **激光俯仰总角度容差** | **≈ atan(2/40.9) ≈ 2.80°** | 含车体扰动 + 云台跟踪误差 + 机械误差 |
| 平衡车典型俯仰抖动 | 静止 ±0.5°~1°；行进 ±1°~3° | 经验值，与控制带宽和地面平整度相关 |

**结论一**：发挥项 2 cm 的波动要求 **不可能仅靠车体平衡精度达成**。必须设计一个 **以 IMU 俯仰角做前馈、视觉光斑做反馈** 的云台稳定环路，把车身抖动主动隔离掉。这点在你现有规划里没有显式提出，是最核心的设计要点。

**结论二**：基础项 4（激光保持在纸上）的难度被低估。纸张高度 ≤25 cm，但纸是包在直径约 6.5 cm 的瓶子上的，正面有效白色面积约 20 cm × 20 cm 上下。只要车辆有一两次大幅倾倒恢复，激光极可能"扫出纸面"。建议 **激光与云台必须从平衡环一稳定就同步上线**，不能放到最后。

## 三、对"项目规划"的逐条批注

### *〔C-1〕* 关于主控芯片（条目 1）

- M0+ 没有 FPU，浮点运算靠软件库或 MathACL。结论：**完全可以跑互补滤波 / 一阶卡尔曼，但跑十五阶 EKF 确实勉强**。所以条目 2 的判断是合理的。
- 真正吃性能的不是平衡解算，而是 **任务并发数 × 中断密度**：编码器双通道捕获、IMU 高频读取、PWM 输出、UART 与 K230 通讯、舵机控制（多路 PWM）—— 这些堆起来才容易把 M0+ 撑爆。建议 **早期就引入轻量任务调度（裸机时间片或 NoOS Cooperative）**，不要写成大杂烩 `while(1)`。

### *〔C-2〕* 关于姿态传感器（条目 2）

- **平衡控制只需要俯仰角与俯仰角速度**，6 轴 MPU6050 + 互补滤波 / Mahony 完全够用，CPU 占用极小。
- MS901M 的优势是"自带四元数 + 磁力计 + 出厂标定"，省事但 **不是平衡所必需**。它的价值在于：① 提供较稳的 yaw 用于圆环上的航向估计（替代视觉短时丢失时的航位推算）；② 给云台偏航做绝对方位参考。
- **建议方案**：先用 MPU6050 把平衡跑通（成本低、调试链路短）；如果后期发现 yaw 漂移影响循迹/云台，再上 MS901M。**不要为了"高级"而把惯性导航 EKF 放到 M0+ 上跑**，那是架构错误的方向。
- ⚠ 注意磁干扰：MS901M 的磁力计会被电机 PWM 严重污染，必须远离电机布置并做软铁/硬铁标定。

### *〔C-3〕* 关于云台（条目 3）

- "尝试自制双自由度云台"：作为学习目标 OK，作为竞赛/项目主线 **不推荐**。理由：
  1. MG90S 是塑料齿模拟舵机，**响应带宽约 5~10 Hz、回程间隙明显、控制分辨率约 1°**。它本身就是 2 cm 精度要求的一个限制因素。
  2. 自制机械结构在零位重复性、轴系刚度、配重平衡上很容易翻车，会反复占用调试时间。
- **建议**：
  - **优先考虑成品云台 + 数字舵机**（MG90S 升级到 SG90 数字版或 LX-225 这类总线舵机；预算允许直接用空心杯无刷云台，带宽可以做到 50 Hz）。
  - 若坚持自制，**俯仰轴务必做配重抵消重力矩**，否则舵机长期堵转损耗大、温升高、精度漂移。
  - 云台俯仰轴的零位与车身水平面的几何关系务必可标定（一个简单的 IMU 零偏 + 机械零偏的两段式标定流程）。

### *〔C-4〕* 关于电机驱动（条目 4）

- TB6612 + 普通减速电机方案没问题。但 **整个规划没有提到电机编码器**，这是一个 **关键缺漏**：
  - 没有编码器 → 没有真实速度反馈 → 没有速度闭环 → 平衡车会出现"贴地慢速漂移"和"前后晃来晃去停不住"。
  - 没有编码器 → 没有里程计 → 没有航位推算 → 视觉短时丢失时无法估计圆环弧长。
  - **强烈建议** 选用带磁编码器（AB 相）的金属齿减速电机，编码线数 ≥ 11 PPR × 30:1 减速比 ≈ 330 线/转 量级。
- TB6612 的 PWM 频率建议 **15~25 kHz**，避开人耳可闻、避开 IMU 通带（IMU 数字 LPF 截止常配 ≤200 Hz）。

## 四、对"执行计划"的逐条批注

### *〔C-6〕* 引脚规划（条目 1）

- 在 M0G3507 上 **优先把"高频中断密集型"外设安排在硬件资源更强的引脚上**：
  - 双路编码器 → TIMG 的 QEI 模式（M0G3507 的 TIMG8 / TIMA0 支持正交解码）。**强烈建议用硬件 QEI，不要用 GPIO 中断软解码**，否则两轮高速时会丢脉冲。
  - IMU → SPI 比 I²C 更稳，I²C 在 400 kHz 下读 14 字节大概 350 µs，会拉低控制频率上限。
  - 舵机 PWM → 同一定时器的多通道，方便相位对齐。
  - K230 通讯 → 独立 UART + DMA，避免阻塞平衡环。
- 引脚表建议在文档里以 **表格形式** 固化下来（信号名 / 方向 / 外设 / 备注），后续硬件改动也以这张表为唯一真源。

### *〔C-7〕* 平衡程序（条目 4，含你提的"是否结合先验数据"）

- 你的疑问 *"是否可以结合轮径、质量、重心位置等先验数据辅助平衡算法？"* — **答案是肯定的，而且非常推荐**：
  - 这本质上是 **从"PD 经验调参"升级到"基于模型的控制"**。
  - 简化为单输入（共模电机扭矩）单输出（俯仰角），把车体当作倒立摆建模 → LQR 一次性给出四个状态（角度、角速度、位置、速度）的最优反馈增益，**比纯 PD 整定快、抗扰好**。
  - 关键先验参数：① 等效轮径 r；② 车体总质量 m；③ 重心到轮轴距离 l；④ 绕轮轴转动惯量 I；⑤ 电机机电时间常数（用一次阶跃响应可辨识）。
  - 这里有个 **常被忽略的坑**：重心高度变化（电池位置、激光器位置、云台姿态变化）会改变 l 和 I，**云台俯仰摆动会让车体平衡参数缓慢漂移**。所以早期就要冻结质心布局。
- 推荐控制结构（级联，从内到外）：

```text
[期望姿态角*]──┐
               ▼
   ┌─────────────────────┐  电机扭矩(共模)  ┌──────┐
   │  俯仰平衡环 PD/LQR  │ ───────────────▶│ 车体 │
   └─────────────────────┘                  └──────┘
            ▲                                  │
            │ 期望角(由速度环输出)              │ θ, θ̇ (IMU)
            │                                  ▼
   ┌─────────────────────┐ ◀──── 车速(编码器)
   │     速度环 PI       │
   └─────────────────────┘
            ▲
            │ 期望速度(由循迹/任务层给)
```

- **建议平衡环 200~500 Hz**（IMU 读取 + 控制输出同步），速度环 50~100 Hz，任务层 / 视觉 20~50 Hz。

### *〔C-8〕* 视觉循迹（条目 6，含你提的两个困惑）

- 你的困惑 *"小车抖动 + 俯仰造成画面透视变化，是否需要 IMU 俯仰信息辅助路径解算？"* — **答案：必须如此**。
  - 标准做法叫 **IPM（Inverse Perspective Mapping，逆透视变换）**：把摄像头看到的图像反映射到地面坐标系。变换矩阵的参数包含 **摄像头安装高度、俯仰角、滚转角**，其中俯仰角必须用 IMU 实时修正，否则反映射会"地面会跳"。
  - 这件事完全可以放在 K230 端做（K230 算力充裕），但 **MSPM0G3507 必须以高频（≥100 Hz）把俯仰角推给 K230**。所以通讯协议设计请预留这条管线。
- 你的困惑 *"是否做铅锤+轴承机械水平摄像头基座？"* — **不推荐作为主线方案**：
  - 你自己的判断完全正确：阻尼调教不应该是项目重心。
  - 替代方案：**摄像头机械固定 + 软件 IPM + 高曝光 / 高帧率**。这条路线已经在很多 ADAS 与无人车上验证成熟。
  - 真要"机械稳像"的话也不该用铅锤被动方案，应该挂在云台俯仰轴上跟随主动稳定 —— 但这又会增加云台负载，得不偿失。

#### 视觉子系统三个独立任务，建议拆开实现：

1. **激光光斑检测**（一个摄像头，朝向瓶子）：UV 纸张本身吸收 UV 后会发出可见荧光（白色纸张 + 405 nm 紫外通常会激发出蓝白色荧光斑）。**用窄带滤光片 + 阈值即可，不需要复杂模型**。输出：光斑在感光纸坐标系的 (Δx, Δy)，作为云台俯仰反馈。
2. **黑线循迹**（另一个摄像头，朝向地面）：经 IPM 后做颜色阈值 + 中线拟合 + 圆弧参数估计。圆环是 **几何先验**：圆心、半径已知，只要估计 **车在圆上的相位角 φ + 横向偏差 e_y**。建议输出 (φ̇, e_y) 给主控。
3. **环上方位估计 / 完成检测**：用 ① 的方位角累计，或在起跑线贴标记，触发"完成一周"事件。

### *〔C-9〕* 云台控制（条目 7）

这一节是项目最关键的控制问题，给出推荐架构：

```text
                      ┌──────────────────┐
   IMU pitch (高频)   │  云台俯仰前馈    │
   ───────────────────▶  补偿 = -k·θ_车  │──┐
                      └──────────────────┘  │
                                             ▼
   光斑位置误差 Δy ──▶ [俯仰反馈 PID] ─▶ ⊕ ─▶ [舵机]
                                             ▲
                                             │
   小车在环上的相位角 φ (开环)───────────────┤
   光斑位置误差 Δx ──▶ [偏航反馈 PID] ───────┘──▶ [偏航舵机]
```

- **俯仰前馈 + 反馈** 是必须组合，单纯反馈追不上车身抖动。
- **偏航主要用开环**：知道车在环上的角度 φ，就知道云台应该转到哪个绝对方位才能对准瓶子；视觉光斑 Δx 只做小幅修正。这样能极大减轻视觉延迟造成的振荡。
- **是否独立 MCU**：你提到了这个问题，给出建议：
  - 如果使用普通 PWM 模拟舵机（如 MG90S），主控生成 50 Hz PWM 即可，**不需要独立 MCU**。
  - 如果使用总线舵机或无刷云台，**强烈建议独立 MCU**（一颗 STM32G0 / GD32E2 即可，跑 1 kHz 控制环），与主控通过 UART 透传期望角度即可。这样云台抖动隔离的高频回路与平衡回路解耦，互不阻塞。

### *〔C-10〕* 其它执行计划缺漏

补充以下条目，建议你纳入"执行计划"：

- **〔C-10.1〕** 通讯协议设计：MSPM0G3507 ↔ K230 ↔（可选）云台 MCU。建议帧格式 `0xAA 0x55 | LEN | CMD | PAYLOAD | CRC16 | 0x55 0xAA`，定义 ≥6 条帧（IMU 同步、循迹结果、光斑位置、云台命令、状态心跳、错误上报）。
- **〔C-10.2〕** 标定流程：IMU 静止零偏标定 / 加速度计 6 面标定 / 磁力计椭球拟合（如用 MS901M）/ 编码器轮径标定 / 舵机机械零位标定 / 摄像头内外参标定。每一项都要有"标定脚本 + 标定结果存 Flash + 一键复测"的闭环。
- **〔C-10.3〕** 任务调度框架：选择 RTOS（FreeRTOS 在 M0G3507 上跑得动）或裸机时间片框架。**先框架后业务**，避免后期返工。
- **〔C-10.4〕** 安全与失效保护：跌倒检测（俯仰角 > 60° 即切断电机 PWM）、电池欠压保护、舵机过流保护、看门狗。
- **〔C-10.5〕** 自主原地起立：这是发挥项最难的一项，本质是 **欠驱动系统的有限时间镇定**。常用策略：
  1. 检测初始倾倒方向；
  2. 反向给两轮一个大幅梯形速度曲线（"先往倒下方向加速→急刹车"），利用反作用把车体甩起来；
  3. 在车体接近垂直时切换到平衡环。
  - 关键参数：起跳力矩、切换角度、切换瞬间的角速度容忍带。建议有专门一个调试模式 + 慢动作录像辅助调参。
- **〔C-10.6〕** 速度优化：题目"行进速度越快越好"是发挥项 4。**先稳定再求快**，速度提升的瓶颈往往不是电机功率，而是过弯时的离心力 + 视觉延迟 + 平衡环增益裕度。建议最后两周再做。

## 七、给本科 / 竞赛团队的几点提醒

1. **平衡车 + 视觉 + 云台的组合**，单人可做，但 3 人分工最佳：① 平衡 / 运动控制；② 视觉 / 通讯；③ 云台 / 机械 / 集成。**不要从头到尾一个人轮着做**，会被调试反复打断。
2. **每一个子系统都建立"独立可调试模式"**：上电按某键进入只调平衡 / 只调云台 / 只调循迹。集成阶段你会感谢自己。
3. **每一个状态量都要可观测**：串口 / 蓝牙 / SD 日志至少留一条。**没有日志的调参等于黑盒掷骰子**。
4. **机械先冻结再调软件**。重心、轮径、传感器位置一旦改动，平衡参数全部要重新整定。
5. **题目里的"硬性时间限制"（不超过 2 秒脱离黑线 / 不超过 2 秒离开纸面）建议在代码里以"软告警阈值"形式打日志**，不要等到测评现场才发现。
