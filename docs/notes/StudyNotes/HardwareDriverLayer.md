# 硬件驱动层 (BSP) 详细解析

## 什么是硬件驱动层 (BSP)?
BSP 全称 Board Support Package（板级支持包）。如果把单片机（MCU）比作大脑，那外围的引脚就是神经。BSP 的作用就是**把这些冷冰冰的硬件电信号，翻译成 C 语言里的函数**，让上层代码可以直接调用。

比如，上层只需要喊一句 `bsp_motor_set_left(500)`，大脑就知道要给左轮输出一半的动力，而不需要去管具体的寄存器要配成 0 还是 1。

## 1. 电机与编码器驱动 (`bsp_motor.c`)
这是小车行驶的“双腿”和感知运动的“眼睛”。

### 1.1 电机怎么动？(TB6612 驱动芯片 与 PWM)
- **原理**：小车使用了一块叫 TB6612 的芯片来放大单片机的信号以驱动大电流的电机。控制它需要两个东西：**方向**和**动力大小**。
- **方向控制**：通过引脚（如 IN1 和 IN2）输出高低电平组合，决定电机是正转、反转还是刹车。
- **动力控制 (PWM)**：单片机引脚只能输出 3.3V (高) 和 0V (低)，没法输出 1.5V 这样的中间电压。**PWM（脉冲宽度调制）**就是让引脚“快速地一开一关”。如果在 1 毫秒内，一半时间开，一半时间关（50% 占空比），电机感受到的平均动力就是一半。
- **代码体现**：在 `apply_one_channel` 函数中，先根据目标速度的正负号设置方向引脚，再调用 `set_pwm_duty` 设置占空比。

### 1.2 怎么知道跑了多远、多快？(编码器)
- **原理**：车轮电机尾部装了霍尔编码器，车轮每转一圈，编码器就会输出几百个电脉冲。数脉冲的数量就知道走了多远，算单位时间内的脉冲增加量就知道有多快。
- **左轮 (硬件 QEI)**：左轮比较“省心”，单片机内部有专门的硬件模块叫 QEI（正交编码器接口），它自己会在后台默默数数，代码只需要偶尔去读一下计数器 (`DL_TimerG_getTimerCount`) 即可。
- **右轮 (GPIO 中断)**：右轮是用普通的 GPIO 引脚接收脉冲的。每当引脚电平发生跳变（上升沿或下降沿），单片机会立刻放下手中的活儿，跳到中断处理函数 `GROUP1_IRQHandler` 中，判断当前是正转还是反转，然后给计数器 `+1` 或 `-1`。
- **速度计算**：在 `bsp_motor_update` 函数里（每 1 毫秒执行一次），代码会积攒一段时间（比如 20 毫秒）的脉冲变化量，用这个差值除以时间，就得出了当前的精确速度。

## 2. 串口通信驱动 (UART)
串口是小车和外部设备（比如姿态传感器、K230视觉模块）交流的“嘴巴和耳朵”。

### 2.1 IMU 姿态传感器通信 (`bsp_imu_uart.c`)
- **挑战**：传感器 (MS901M) 会源源不断地以每秒 200 次的速度发来姿态数据。如果单片机每次只收一个字节就去处理，会被频发的中断“烦死”，影响平衡计算。
- **环形缓冲区 (Ring Buffer)**：代码里建了一个 256 字节的“环形水池”。单片机的硬件串口每次收到一批数据，就触发一次中断（半满中断），把数据倒进水池里。主程序只要在有空的时候（每毫秒一次），拿个大桶去水池里一次性捞走积攒的数据 (`bsp_imu_uart_rx_pop_bulk`) 交给上层解析就行了。

### 2.2 K230 视觉模块通信 (`bsp_k230_uart.c` & 中断驱动)
- **FIFO 半满中断**：这是当前使用的方案。串口收到数据存到 FIFO 中，达到半满阈值（如 4 字节）时触发一次中断，ISR 把数据搬进 512 字节**环形缓冲区**。主循环在 1 kHz 节拍中从环缓捞取数据。这种方式比 DMA 更简洁，没有"搬运完一整块再通知"的延迟，也没有 DMA 自动重装配置的复杂度。
- **历史**：早期版本曾使用 DMA block 模式，在 Stage 4 v0.8 被替换为当前的中断驱动方案。

## 3. 电池监测驱动 (`bsp_battery.c` & ADC)
小车用的是 3S 锂电池，如果电压太低（过放电）会永久损坏电池甚至引发危险。

- **ADC (模数转换器)**：用来把模拟的真实电压（比如 11.4V）变成单片机能看懂的数字。
- **软件触发机制**：代码没有用复杂的中断去读电池，而是每次主循环（每 10 毫秒）主动要求 ADC 进行一次转换 (`trigger_conversion`)，并稍微等几微秒拿结果。
- **滤波抗干扰 (EMA)**：重点来了！电机启动或急刹时，电池电压会“忽上忽下”剧烈波动。为了防止单次低压导致小车误触发急停，代码里用了一个叫 EMA（指数移动平均）的算法：
  `新结果 = (大部分的老结果) + (一小部分的新测量值)`
  这样就像给电压数据加了“减震器”，只有电压真的**持续下降**，系统才会确认电池没电了，从而触发保护。

## 4. 系统心跳定时器 (`bsp_systick.c`)
这是整个小车生命节拍的源泉。

- **原理**：单片机内核里有一个专门的硬件定时器叫 SysTick。它被配置成每 **1 毫秒** 准时触发一次中断。
- **时间戳**：每次中断，就会让一个全局变量 `s_tick_ms` 加 1。这个变量就是整个小车的时间基准。
- **最高优先级**：代码中故意把 SysTick 的中断优先级设为**最高 (0)**，把编码器的 GPIO 中断设为最低 (3)。这意味着：无论车轮转得多快、编码器产生多少干扰中断，都**绝对不能打断时间的流逝**。这保证了 PID 平衡控制算法的绝对准时，这也是让小车站得稳的关键细节之一。

**初学者建议：**
阅读这部分代码时，可以先跳过复杂的寄存器配置（如 `ti_msp_dl_config.c` 里自动生成的代码），把注意力放在各个模块暴露给上层的 **公共 API 函数**（比如 `bsp_motor_set_left`，`bsp_battery_get_mv`）上，理解它们是如何把硬件操作包装成好用的函数的。
