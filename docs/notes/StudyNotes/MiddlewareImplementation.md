# 中间层 (Middleware) 代码实现路径详解

上一篇文档中我们从概念上讲了中间层在做什么。这篇文档我们将深入到具体的代码实现，看看 C 语言是如何把抽象的数学公式和协议解析落地的。这部分重点剖析 `ms901m.c` 和 `pid.c` 这两个文件。

---

## 1. 姿态解析器的底层实现 (`ms901m.c`)

这个文件虽然不涉及单片机的寄存器，但它对 C 语言中“状态机”和“数据类型转换”的应用非常经典。

### 1.1 状态机的高效运转 (`ms901m_feed_bytes`)
当你有一大串乱序的字节流入时，如何保证不漏掉任何一帧？
代码中使用了一个 `switch(s_state)` 语句，配合一个枚举类型 `parse_state_t`。
- **状态转移逻辑**：
  - 在 `ST_SYNC1` 状态下，只认 `0x55`。一旦收到，状态立马变成 `ST_SYNC2`。
  - 在 `ST_SYNC2` 状态下，再收一个 `0x55`，状态变成 `ST_ID`。
  - 如果在中间任何一个环节发现数据不对（比如校验和算出来对不上），状态机会调用 `reset_state_machine()`，把状态强行拨回 `ST_SYNC1`，并且把校验和清零，等待下一个 `0x55`。
- **为什么要这样写？**
  这种写法被称为**“非阻塞式解析”**。每次传入一个字节，函数只做极少量的判断就立刻返回，不会在里面用 `while` 循环死等数据。这对于需要保证 1 毫秒节拍准时执行的单片机系统来说至关重要。

### 1.2 字节拼接与量纲转换 (`parse_attitude` / `parse_gyro_acc`)
传感器发来的角度数据是被拆成两个 8 位字节（高位和低位）发送的。
- **拼接 (Little-Endian)**：
  代码里写了一个小工具函数 `le16(uint8_t lo, uint8_t hi)`，它通过位移操作 `(hi << 8) | lo` 把两个 8 位的碎片拼成了一个 16 位的有符号短整数 (`int16_t`)。
- **量纲转换 (Q15 格式还原)**：
  传感器为了省空间，把 $-180^\circ$ 到 $+180^\circ$ 映射到了 $-32768$ 到 $+32767$ 的整数范围。
  代码中的还原公式：
  ```c
  s_snap.pitch_deg = (float)le16(d[2], d[3]) * (180.0f / 32768.0f);
  ```
  编译器在编译时，会提前把 `180.0f / 32768.0f` 算成一个固定的常数。单片机运行时，只需做一次浮点乘法，极大提升了执行速度。

## 2. PID 算法的落地细节 (`pid.c`)

理论上的 PID 是微积分公式，但在代码里，它被离散化成了一拍一拍的加减乘除。

### 2.1 P (比例)、I (积分)、D (微分) 的代码映射 (`pid_step`)
在这个函数中，每隔固定时间（`dt_sec`，在这个项目里是 0.01 秒，即 100Hz）被调用一次。

- **比例项 (P)**：最简单，直接乘。
  ```c
  float p_term = pid->kp * error;
  ```
- **积分项 (I) 离散化**：微积分里的积分，在代码里其实就是**累加（求面积）**。
  ```c
  float i_inc = pid->ki * error * dt_sec; // 算出这一小段时间的面积
  float i_try = pid->i_term + i_inc;      // 累加到历史总和里
  ```
- **微分项 (D) 离散化**：微积分里的导数，在代码里其实就是**求斜率（变化率）**。
  ```c
  float d_meas = (measured - pid->prev_meas) / dt_sec; // (现在的值 - 过去的值) / 时间差
  d_term = -pid->kd * d_filt;
  ```

### 2.2 两个极其重要的“工业级”保护机制
教科书上的 PID 只有上面那三行，但在真实的机器人控制里，如果不加保护，车早就撞碎了。`pid.c` 里加了两个关键保护：

#### ① 微分先行与低通滤波 (D Filter)
- **微分先行**：仔细看代码，D 兄弟不是对 `error` 求导，而是对 `measured`（测量值）求导。为什么？因为如果我们在遥控时突然改变目标速度（目标值发生阶跃），`error` 瞬间变大，普通的 D 会输出一个极大的尖峰电流，导致车剧烈抽搐。而 `measured`（真实的倾角或速度）是物理量，不能突变。所以只对测量值求导，叫“微分先行”，能平滑应对遥控指令。
- **低通滤波 (`d_filter_alpha`)**：传感器的数据总是有噪点的。如果直接求导，噪点会被无限放大。代码里用了一个一阶低通滤波器公式：
  `d_filt = alpha * 当前导数 + (1 - alpha) * 上次导数`
  把剧烈跳变的导数抹平，让电机声音更柔和。

#### ② 积分抗饱和 (Anti-Windup)
这是控制领域最容易踩坑的地方。
- **情景**：假如有人一直推着小车不让它走，小车的 `error` 一直存在，I 兄弟就会一直累加，直到累加出一个天文数字。等你松开手，小车为了消耗掉这个天文数字，会像疯了一样冲出去。
- **代码实现**：
  ```c
  bool saturated_high = (u >= pid->u_max) && (u_raw >= pid->u_max);
  if (saturated_high && i_inc > 0.0f) {
      // 已经限幅了，且还在往更大的方向累加，就不更新 i_term 了！
  } else {
      pid->i_term = i_clamped;
  }
  ```
  如果发现电机输出已经到了极限（满油门了），并且积分还要继续加，代码就果断**切断积分的累加**。一旦偏差反转，积分能立刻退出来。这叫“条件积分抗饱和”，保证了小车在被阻挡后松开手，不会“窜出去”。

---

**总结：**
中间层的代码量虽然不大，但含金量极高。`ms901m.c` 展现了如何用状态机写出不卡顿的数据解析器；而 `pid.c` 则展现了如何把理论上的数学公式，加上抗饱和、低通滤波等工业级保护，变成能在真实物理世界稳定运行的控制代码。
