# 应用层 (App) 详细解析

应用层是整个项目的"总指挥"。它不需要去管怎么拉高低电平，也不需要自己去写复杂的数学公式，它的任务是**把底层硬件 (BSP) 和中间算法 (Middle) 像搭积木一样拼起来，实现小车真正的行为逻辑**。

本项目的应用层包含四个核心模块：安全管家 (`app_safety.c`)、平衡大脑 (`app_balance.c`)、圆弧运动 (`app_circle_demo.c`) 和电机测试 (`app_motor_demo.c`)。

---

## 1. 安全管家 (`app_safety.c`)

这是小车的"保命系统"。平衡车一旦失控，轮子全速旋转会非常危险；同时，锂电池如果过放电会直接报废。因此，在执行平衡控制之前，必须先过安全管家这一关。

### 1.1 状态机设计
安全管家内部维护了一个清晰的状态机，主要有以下几种状态：
- **`DISARMED` (解除武装)**：默认的待机状态，电机不通电。按下板子上的 S1 按键可以切换到 `ARMED`。
- **`ARMED` (武装状态)**：正常工作状态，电机可以自由转动。
- **`FALLEN` (跌倒保护)**：当传感器检测到小车倾角超过了危险值（倾斜 > 60 度，说明车已经摔在地上了），安全管家会立刻掐断电机动力，防止车轮在地上疯狂空转。
- **`LOW_BAT_WARN` (低压警告)**：电池快没电了，安全管家会限制电机的最大输出功率（限速），并让红灯闪烁。
- **`LOW_BAT_STOP` (低压急停)**：电池电量达到了危险底线，安全管家会彻底锁死电机（刹车并切断动力），这时候按 S1 也无法启动，必须更换电池。

> **栈保护 (v2.0)**：安全管家的状态变量用 canary 魔数包裹。如果栈溢出写脏了安全状态，`app_safety_get_state()` 会检测到非法值或 canary 损坏，自动复位到 `DISARMED` 并打印 `[safety] CORRUPTION`。

### 1.2 它是如何介入的？
在平衡大脑计算电机该出多大力的前一刻，会先调用 `app_safety_tick` 函数把当前的角度和电池状态汇报给安全管家。只有安全管家返回 `true`（允许行驶），电机才会被允许转动。

## 2. 平衡大脑 (`app_balance.c`)

这是小车最核心的逻辑文件，负责统筹大局和执行平衡算法。

### 2.1 多级 PID 控制链（`pid2_t`）

`app_balance.c` 使用与 STM32 demo 对齐的 **`pid2_update()`** 控制器，共四路：

**俯仰链（两级）**：
1. **速度环 (`speed_pid`，20 Hz)**：输入 = 归一化速度 vs `target_speed_cps`，输出 = `target_tilt_deg`（°），限幅 ±10°。目标经 EMA 低通平滑。
2. **角度环 (`angle_pid`，100 Hz)**：输入 = 目标倾角 vs 实测 pitch，**直接输出平均 PWM**（‰）。含 OutOffset 突破死区，Kd 微分先行。

**横摆链（三级）**：
3. **航向角环 (`yaw_pid`，20 Hz)**：反馈 = `yaw_deg`（EKF）或 `gz` 积分，输出 = 差速环目标（归一化 cps）。
4. **差速环 (`diff_pid`，20 Hz)**：输入 = 差速目标 vs 实测差速（RPM 量纲），输出 = 差分 PWM。限幅 ±600‰。

**最终合成**：`left = angle_out + diff_out`，`right = angle_out − diff_out`。

> 注：早期版本曾有独立角速度内环 (`rp`) 与轮速差转向环 (`tp`)，已在 Stage 3.7 移除。Stage 3.8 新增差速闭环将航向环输出改为差速环目标。调参见 [PIDTuningGuide.md](PIDTuningGuide.md)。

### 2.2 小车的主循环节拍 (`app_balance_run`)

| 频率 | 任务 |
|------|------|
| 1 kHz | IMU drain (`ms901m_feed_bytes`)、K230 帧 drain、`bsp_motor_update` |
| 100 Hz | MS901M 快照、安全检测 (`app_safety_tick`)、**角度环 + 电机输出** |
| 20 Hz | 速度环、航向角环、差速环、`app_circle_demo_tick`、K230 状态上报 + 心跳 TX |
| 5 Hz | LED 心跳 + 安全指示 |
| 1 Hz | 串口调试日志（含 `pitch`/`tilt*`/`pwm`/`yawErr`/`yawCorr`/`difTgt`/`difOut`） |

## 3. 圆弧运动演示 (`app_circle_demo.c`)

这是 Stage 3.9 新增的子任务，寄生在 20 Hz 分支中，支持平衡车在直立状态下执行指定直径 + 速度的整圆轨迹运动。

- **串口触发**：`c`/`circle [直径mm] [速度mm/s]` → 启动；`cx` → 中止
- **三重判停**：① IMU `gz_dps` 积分 ≥ 360°（主判据）② 编码器弧长 ≥ 周长×1.2（备判据）③ 超时兜底
- **运动学计算**：依赖 `robot_param.h` 将直径+速度换算为 `avg_cps` 和 `delta_cps`，分别填入速度环和差速环目标
- **激活时**覆盖 `cmd->target_speed_cps` / `cmd->target_dif_cps`，非激活时不做任何写入

## 4. 电机测试模式 (`app_motor_demo.c`)

在刚组装好小车，还没调好平衡参数时，直接让小车自平衡是很危险的。
- 上电默认进入装车模式（`app_balance_run`），串口发 `t` 或 `test` 切入电机演示
- 可串口调速（`+`/`-`/数字回车）、急刹（`b`）、开关同步（`s`）、校准扫描（`c`/`x`）
- 演示中发 `l` 或 `load` 返回装车模式

---

**初学者建议：**
应用层是你以后写代码最常修改的地方。如果你想改变小车的行为，比如加一个超声波避障，你应该在 `app_balance_run` 的时间片里（比如加一个 50 毫秒任务）去读取超声波数据，然后去修改速度环的"目标速度"。
不要去破坏现有的 10ms 控制环和 1ms 数据读取环，它们是小车赖以生存的根基。理解了 `app_balance.c` 的多级 PID 链，你就能随心所欲地控制这台小车了！
