# 中间层 (Middleware) 详细解析

中间层（Middle）是位于底层硬件驱动（BSP）和顶层应用逻辑（App）之间的一层。
它的特点是：**它不关心具体的硬件引脚是哪个，它只专注于"处理数据"和"数学算法"**。

这就好比底层驱动负责把食材（电信号）洗好切好，中间层负责提供菜谱和烹饪方法（算法），而应用层则是最后决定今天吃什么的大厨。

在本项目中，中间层包含多个核心模块：`ms901m.c`（姿态数据解析）、`pid.c`（PID 控制算法）、`k230_protocol.c`（K230 通讯协议）、`robot_param.h`（车体运动学）。

## 1. MS901M 姿态传感器解析 (`ms901m.c`)

MS901M 是一块内置了算法的姿态传感器（里面自带了卡尔曼滤波等高级算法），它会源源不断地通过串口发送数据出来。但它发出来的都是计算机才能看懂的二进制字节流，比如 `0x55 0x55 0x01 0x06 ...`。这个模块的任务就是把这些字节翻译成人类能看懂的"度数"。

### 1.1 数据是怎么打包的？（通信协议）
传感器发出的数据是有严格格式的，我们称之为"数据帧"。一帧数据就像一个包裹：
- **包头 (SYNC1, SYNC2)**：固定是 `0x55 0x55`，告诉你"注意啦，新包裹来了！"
- **标签 (ID)**：告诉我们包裹里装的是什么。比如 `0x01` 代表里面是角度（Pitch, Roll, Yaw），`0x03` 代表里面是加速度和角速度。
- **长度 (LEN)**：告诉你包裹里的内容有几个字节。
- **内容 (DATA)**：真正的数据。
- **封条 (CHECKSUM)**：校验和。发送方把前面的数据加起来算出一个数放在最后，接收方收到后也加一遍，如果两个数对得上，说明数据在路上没出错。

### 1.2 怎么拆包裹？（状态机解析）
在 `ms901m.c` 的 `ms901m_feed_bytes` 函数中，使用了一个经典的**"状态机"**机制来拆包裹。
想象一下你在流水线上检查包裹：
1. **找包头 (`ST_SYNC1`, `ST_SYNC2`)**：死死盯着传过来的字节，只有连续看到两个 `0x55`，才确认包裹开始。
2. **看标签和长度 (`ST_ID`, `ST_LEN`)**：记下这是什么类型的数据，有多长。
3. **收数据 (`ST_DATA`)**：把数据暂存到一个数组里，直到收够了长度。
4. **验封条 (`ST_CHECKSUM`)**：核对校验和。如果对了，就把数据交给专门的函数去"翻译"；如果错了，说明包裹坏了，直接扔掉。

### 1.3 翻译数据
当收到正确的数据后，比如角度数据（ID 是 0x01），代码会调用 `parse_attitude` 函数。
传感器发来的角度是被放大压缩过的（为了节省空间）。代码里有一行核心运算：
```c
s_snap.pitch_deg = (float)le16(d[2], d[3]) * (180.0f / 32768.0f);
```
它的意思就是把两个字节拼成一个 16 位的整数，然后按照传感器的说明书，把它按比例还原成真实的带小数的度数（比如倾斜了 15.3 度）。最后，把这些整理好的数据放到一个叫 `s_snap`（快照） 的结构体里，供上层随时读取。

## 2. PID 控制算法 (`pid.c`)

这是让小车能站稳的核心数学算法。PID 全称是"比例-积分-微分"（Proportional-Integral-Derivative）。

项目中提供了**两套 PID 控制器**：当前平衡控制使用的是 **`pid2_t`**（对齐 STM32 demo），旧 `pid_t` 保留供参考。

### 2.1 为什么需要 PID？
假设小车现在往前倾斜了 10 度，我们想让它回到 0 度（直立）。如果只写一句代码："只要倾斜了，电机就全速倒转"，你会发现小车会剧烈晃动，甚至直接朝反方向摔倒。
PID 就是为了解决这个问题，它能计算出一个**"恰到好处"**的力度。

### 2.2 `pid2_t` —— 当前平衡车使用的控制器（`pid2_update`）

- **P (比例) — "现在差多少，就使多大劲"**
  ```c
  float error = p->target - p->actual;
  // u_raw = kp * error + ...
  ```
  `error` 就是误差。偏差越大，P 输出的力度就越大，反应最快但容易冲过头。

- **I (积分) — "按拍累加，Ki=0 自动清零"**
  ```c
  if (p->ki != 0.0f) {
      p->i_term += error;   // 每拍直接累加（不乘dt）
      p->i_term = clampf(p->i_term, p->i_min, p->i_max);
  } else {
      p->i_term = 0.0f;     // ★ 关键：Ki=0 自动清零！
  }
  ```
  如果小车一直回不到 0 度（重心偏移），P 兄弟觉得偏差太小不想出力。I 兄弟把过去微小偏差累加起来，直到力量够大。
  
  **核心创新**：Ki=0 时积分自动清零——调参阶段关掉积分不会残留"积分债务"，这是对齐 STM32 demo 的关键改进。

- **D (微分) — "微分先行，防止冲过头"**
  ```c
  float d = p->has_prev ? (p->actual - p->prev_actual) : 0.0f;
  // u_raw = ... - kd * d
  ```
  D 兄弟专门看**测量值的变化速度**（不是误差的变化！），这叫**"微分先行"（D on measurement）**。对测量值微分而非误差微分，能平滑应对遥控指令的突然跳变（setpoint 阶跃不会产生 D 项冲击）。

### 2.3 `pid2_t` 独有的 OutOffset —— 死区补偿

```c
if (u > 0.0f)      u += p->out_offset;
else if (u < 0.0f) u -= p->out_offset;
```

电机驱动芯片 TB6612 有**静摩擦死区**：PWM < 60‰ 时电机完全不转。PID 输出 30‰ 时电机不动，到 61‰ 突然跳起来 → 方波振动。

`out_offset` 在非零输出上叠加恒定偏置（典型 60~100‰）：只要 PID 有输出意图（哪怕 1‰），就能突破死区真正驱动电机。串口命令 `bo 80` 或 `bp 5000 0 5000 80` 的第 4 个参数就是设置它。

### 2.4 旧 `pid_t`（保留供参考）

旧控制器 `pid_step()` 更接近教科书 PID：传 `dt_sec`、含抗积分饱和、D 项 EMA 低通。当前平衡车已切换到 `pid2_t`，但 `pid_t` 仍在代码库中可供其他模块选用。

### 2.5 中间层的独立性
`pid.c` 里没有任何跟电机或引脚相关的代码。它只接受数字（目标值、当前值），吐出一个数字。明天做无人机、恒温烤箱，直接拷走 `pid.c` 就能用。这就是中间层的价值。

## 3. 车体运动学 (`robot_param.h`)

这是 Stage 3.9 新增的模块，集中管理小车的**物理几何参数**与**运动学换算**。

### 3.1 为什么需要集中管理？
之前轮径（65 mm）、轴距（185 mm）等参数散落在 `app_balance.c`、`app_circle_demo.c` 各处，改了轮子要改多个文件。`robot_param.h` 把它们收归一处：

```c
#define ROBOT_WHEEL_DIAMETER_MM   (65)   // 轮胎外径，含橡胶
#define ROBOT_WHEEL_BASE_MM       (185)  // 左右轮中心间距
```

每个宏带 `#ifndef` 包裹，支持编译期 `-D` 覆盖——实测后改一个数字就能全局生效。

### 3.2 inline 运动学换算
```c
// 线速度 mm/s → 编码器 counts/s
v_mm_s * AVG_COUNTS_PER_MM_X100 / 100

// 编码器计数 → 行驶弧长 mm
avg_counts * 100 / AVG_COUNTS_PER_MM_X100

// 角速度 mrad/s → 左右差速 counts/s
omega_mrad * WHEEL_BASE_MM * AVG_COUNTS_PER_MM_X100 / (100 * 1000)
```

全部 inline 函数 + 编译期常量，**零运行时浮点开销**，Cortex-M0+ 友好。

---

**初学者建议：**
先搞懂 `pid2_update` 中 `error` 怎么来、P/I/D 怎么加到一起、`out_offset` 为什么能突破死区。`pid2_t` 比传统 `pid_t` 更简洁、更适合嵌入式平衡车。`ms901m.c` 重点理解 `switch-case` 状态机。`robot_param.h` 体现了"参数集中管理 + 编译期计算"的嵌入式工程好习惯。
