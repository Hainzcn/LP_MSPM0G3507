# 硬件驱动层 (BSP) 代码实现路径详解

在上一篇文档中，我们从“概念”上了解了驱动层的作用。这篇文档我们将深入到具体的代码文件（`.c`），详细看看这些驱动在 **MSPM0G3507 单片机** 上到底是调用了什么接口、用什么逻辑来实现的。

这部分内容适合你想自己动手修改底层逻辑，或者想学习德州仪器（TI）单片机用法的阶段。

---

## 1. 电机与编码器 (`bsp_motor.c`)

这个文件是底层代码最丰富的一个，因为它既要管输出（PWM），又要管输入（编码器脉冲），还要处理硬件噪声。

### 1.1 PWM 怎么输出的？(定时器 TimerA)
代码中改变电机速度的根本途径是调用了 `set_pwm_duty` 函数。
- **底层接口**：`DL_TimerA_setCaptureCompareValue(...)`
- **逻辑**：它不是直接填一个百分比，而是填一个“计数值”。单片机的定时器一直在从 0 数到 `load`（最大周期值）。我们通过改变 `compare`（比较值），让引脚在这个比较值时翻转电平，从而实现占空比的改变。

### 1.2 右轮编码器软件解码 (`GROUP1_IRQHandler`)
左轮有硬件 QEI 帮忙数数，但右轮只能靠软件中断。
- **入口**：在 `GROUP1_IRQHandler` 中，只要 PA12 或 PA13 引脚电平跳变，就会触发。
- **解码逻辑** (`on_right_encoder_edge`)：
  这里用了一个非常巧妙的逻辑表达式 `(phase_a != phase_b)`。
  当 A 相发生跳变时，去读一下当前的 A 和 B 电平：如果 A 不等于 B，说明是正转，脉冲 `+1`；如果 A 等于 B，说明是反转，脉冲 `-1`。
- **抗雪崩机制**：为了防止线没插紧导致几万次噪声中断把单片机“卡死”，在 `bsp_motor_update()` 里有一个检查：如果 1 毫秒内中断次数超过 200 次，单片机会**主动关闭中断 50 毫秒**，让 CPU 喘口气，这叫“中断雪崩兜底”。

## 2. 串口通信：环形缓冲与 DMA

处理串口数据最怕的就是“漏收”。单片机处理数据的速度如果不匹配，数据就会被覆盖。

### 2.1 IMU 姿态接收 (`bsp_imu_uart.c`)
这里使用了经典的 **无锁环形缓冲 (Lock-free Ring Buffer)**。
- **写数据 (ISR)**：在 `UART3_IRQHandler` 串口中断里，硬件只要收到一半的数据（半满），就会触发。中断函数只负责把数据写进 `s_rx_buf`，然后把 `s_rx_head` (写指针) 往前推。
- **读数据 (App)**：主程序通过 `bsp_imu_uart_rx_pop_bulk` 去读。它从 `s_rx_tail` (读指针) 一直读到 `s_rx_head`。
- **为什么安全？** 这里的巧妙之处在于把缓冲大小设为 256（2 的幂）。写到 255 再加 1 会自动变成 0，而且 16 位的指针在单片机上读写是一次性完成的（原子的），所以连关中断保护都不需要。

### 2.2 K230 视觉接收 (`bsp_k230_uart.c`)
这里用了 **DMA (Direct Memory Access)**。
- **底层接口**：`DL_DMA_setSrcAddr`（设置源地址为串口寄存器）和 `DL_DMA_setDestAddr`（设置目标地址为内存数组）。
- **逻辑**：一旦开启，串口收到字节就会自动跑到数组里。满 512 字节后触发 `DMA_IRQHandler` 中断。
- **补丁逻辑**：因为这款单片机的串口 RX DMA 不支持“自动重装”，所以在中断里，代码必须手动调用 `k230_dma_rx_arm()` 重新配置一遍 DMA，让它继续下一轮搬运。

## 3. 电池 ADC 采样 (`bsp_battery.c`)

电池采样最大的特点是“轻量化”：不占用宝贵的中断资源。

### 3.1 纯软件触发与轮询
- **触发**：通过 `DL_ADC12_startConversion` 告诉 ADC 开始转换。
- **等待**：不使用中断，而是用了一个 `for` 循环 (`wait_conversion_done`)。因为 ADC 转换极快（不到 5 微秒），循环读取 `DL_ADC12_getRawInterruptStatus` 等待完成标志位，比进出中断还要快，省去了中断上下文切换的时间。

### 3.2 整数运算替代浮点
为了算真实电压，公式应该是 `电压 = 原始值 * 3.3V / 4095 / 分压比`。
如果在 C 语言里直接写小数（如 `* 3.3`），单片机会引入庞大的软浮点计算库，拖慢速度。
- **实现**：代码里巧妙地全部使用了 32 位无符号整数乘除法（例如乘 10000 变大，最后再除），在 `bsp_battery_raw_to_mv` 中实现了 0 浮点的精确计算。

## 4. 系统心跳 SysTick (`bsp_systick.c`)

这是控制系统脉搏跳动的地方，看似简单，实则暗藏玄机。

### 4.1 优先级魔改
- **问题**：在标准库 `SysTick_Config` 中，默认会把滴答定时器的中断优先级设为**最低 (3)**。这意味着任何一个外部干扰（比如碰了一下编码器线），都能抢占时间，导致时间停滞。
- **实现**：代码在调用完配置后，强制执行了 `NVIC_SetPriority(SysTick_IRQn, 0u)`。把优先级提到了**最高 (0)**。这属于底层开发中的“黑魔法”，强制保证了时间基准的绝对可靠，无论外界怎么干扰，1 毫秒必须准时跳动。

### 4.2 拦截 HardFault (硬件错误)
- **实现**：在文件最底部，代码重写了 `HardFault_Handler`。原本单片机遇到底层错误（比如指针越界）会进入死循环（假死）。代码将其改成了 `NVIC_SystemReset()`（直接重启）。这样如果遇到干扰导致死机，单片机会秒速重启，而不是变砖，极大地提升了调试体验。

## 5. GPIO 初始化补丁 (`bsp_gpio.c`)

- **为什么要手写？** 很多引脚可以直接用 SysConfig 图形化配置，但 SDK 2.10 版本在生成代码时存在缺陷，不会自动给输入引脚加上拉电阻和滤波。
- **实现**：为了解决这个问题，代码手工调用了 `DL_GPIO_initDigitalInputFeatures`。
  - 强制开启 `DL_GPIO_RESISTOR_PULL_UP`（内部上拉，防止引脚悬空时电平乱跳）。
  - 强制开启 `DL_GPIO_HYSTERESIS_ENABLE`（施密特触发器，用来滤除微小的电平毛刺）。
  正是这几行手工代码，保住了编码器中断不被噪声淹没。
