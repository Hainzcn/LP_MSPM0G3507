# BSP_IMU_UART IMU 串口接收模块 学习笔记

## 📖 一、整体概述

### 1.1 这个模块在项目中的位置

本项目是一个**两轮自平衡瞄准小车**，主控为 **TI MSPM0G3507**。

`bsp_imu_uart` 是硬件驱动层中连接 MS901M 姿态传感器的"桥梁"——它通过 UART3 接收 MS901M 持续发送的二进制数据帧，把这些字节存入环形缓冲区，供 ms901m.c 解析器取用。

```
┌──────────────────────────────────────────────────────────────┐
│                    ms901m.c                                   │
│  ms901m_feed_bytes(buf, n) —— 解析姿态数据                    │
└────────────────────▲─────────────────────────────────────────┘
                     │ pop_bulk 取出批量字节
┌────────────────────┴─────────────────────────────────────────┐
│                 bsp_imu_uart.c（本模块）                      │
│                                                              │
│  环形缓冲区（256 字节）：                                     │
│  ┌────┬────┬────┬────┬────┬────┬────┬────┐                  │
│  │ 55 │ AF │ 01 │ 06 │ 12 │ 34 │ 56 │ 78 │ ...              │
│  └─▲──┴──▲─┴────┴────┴────┴────┴────┴────┘                  │
│    tail  head                                                │
│    (主循环读) (ISR 写)                                        │
└────────────────────▲─────────────────────────────────────────┘
                     │ ISR 逐字节写入
┌────────────────────┴─────────────────────────────────────────┐
│          UART3 硬件 + PB12 TX / PB13 RX 引脚                  │
│          115200 8N1，RX FIFO 半满中断                         │
└──────────────────────────────────────────────────────────────┘
                     ▲
                     │ MS901M 持续发送二进制帧（200 Hz）
```

### 1.2 本工程中的三个 UART

| 模块 | 硬件 | 用途 | 方向 | 数据率 |
|------|------|------|------|--------|
| **bsp_imu_uart** | UART3 (PB12/PB13) | 接收 MS901M 姿态数据 | 主要 RX | ~15 KB/s |
| bsp_log_uart | UART0 (XDS110 USB) | printf 调试日志 | 主要 TX | 低 |
| bsp_k230_uart | UART2 | 与 K230 视觉通讯 | 双向 | 待定 |

### 1.3 核心机制：生产者-消费者模式

```
生产者（ISR）             缓冲区                   消费者（主循环）
───────────────      ──────────────              ─────────────────
UART3_IRQHandler    环形缓冲区 256B               bsp_imu_uart_rx_pop_bulk()
    │                                              │
    ├─ 收到字节 b → s_rx_buf[head]                 ├─ 读取 buf → 喂给
    │  head++                                      │  ms901m_feed_bytes()
    │                                              │
    └─ 周而复始                                    └─ 每 1 ms 一次
```

## 📋 二、函数与变量汇总

### 2.1 静态变量

| 变量名 | 类型 | 修饰 | 初始值 | 含义 | 谁写 | 谁读 |
|--------|------|------|--------|------|------|------|
| `s_rx_buf[256]` | `uint8_t[]` | `volatile` | 全 0 | 环形缓冲区 | ISR | 主循环 |
| `s_rx_head` | `uint16_t` | `volatile` | 0 | 写指针（下一个写入位置） | ISR | ISR / 主循环 |
| `s_rx_tail` | `uint16_t` | `volatile` | 0 | 读指针（下一个读取位置） | 主循环 | ISR / 主循环 |
| `s_rx_overrun` | `uint32_t` | `volatile` | 0 | 溢出次数 | ISR | 主循环 |

### 2.2 宏定义

| 宏 | 值 | 用途 |
|----|-----|------|
| `IMU_RX_BUF_SIZE` | 256 | 环形缓冲区大小（2 的幂） |
| `IMU_RX_BUF_MASK` | 255 | 取模掩码（位运算代替 %） |

### 2.3 函数汇总

| 函数名 | 功能 | 何时调用 |
|--------|------|---------|
| `bsp_imu_uart_init()` | 初始化 UART3 + 使能 NVIC + 复位环形缓冲 | main 初始化一次 |
| `bsp_imu_uart_write()` | 阻塞式发送数据到 MS901M | 发送配置命令时 |
| `bsp_imu_uart_rx_pop()` | 从环形缓冲区取一个字节 | 单字节处理 |
| `bsp_imu_uart_rx_pop_bulk()` ⭐ | 批量从环形缓冲区取字节 | **主循环每 1 ms** |
| `bsp_imu_uart_rx_available()` | 查询缓冲区可读字节数 | 诊断/调试 |
| `bsp_imu_uart_rx_overrun()` | 查询累计溢出次数 | 监控通信质量 |
| `UART3_IRQHandler()` | ISR：FIFO→环形缓冲区 | 每收到数据自动触发 |

## 🔄 三、核心逻辑总结

### 3.1 环形缓冲区工作原理

```
空缓冲区：
  head=0  tail=0
  [...空...]
  ↑head/tail

写入 3 个字节（ISR）：
  head=3  tail=0
  [55][AF][01][...空...]
         ↑tail    ↑head

读取 2 个字节（主循环）：
  head=3  tail=2
  [55][AF][01][...空...]
               ↑head
          ↑tail

头尾相遇 → 缓冲区空
头尾+1 相遇 → 缓冲区满
```

### 3.2 关键设计：为什么需要 `NVIC_EnableIRQ`？

SysConfig 配置 UART 中断有两步：
1. **外设级**：设置 UART 的 IMSC（中断掩码）寄存器，告诉 UART 硬件"产生中断信号"
2. **NVIC 级**：设置 NVIC 的 ISER 寄存器，告诉 CPU "响应这个中断"

SysConfig **只做第 1 步**，不做第 2 步。所以必须手动调用 `NVIC_EnableIRQ(UART_IMU_INST_INT_IRQN)`。

如果不加这行：
```
MS901M 发送数据 → UART 收到 → FIFO 半满 → UART 产生中断信号
→ NVIC 收到信号 → 但 NVIC 没有使能这个通道 → 信号被忽略
→ ISR 永不触发 → head 永不前进 → ms901m_has_attitude 永为 false
→ main() 超时 fatal
```

### 3.3 数据率估算

```
MS901M 出厂配置（5 帧全部上报，200 Hz）：
  帧 0x01（姿态）：6 字节数据 + 5 字节开销 = 11 字节
  帧 0x02（四元数）：8 + 5 = 13 字节
  帧 0x03（陀螺+加速度）：12 + 5 = 17 字节
  帧 0x04（磁力+温度）：8 + 5 = 13 字节
  帧 0x05（气压+高度）：10 + 5 = 15 字节
  每周期 ≈ 69 字节
  每秒 ≈ 69 × 200 ≈ 13,800 字节/s

115200 bps 有效数据率 ≈ 11520 字节/s
```

由于带宽限制，实际项目中应通过 `ms901m_build_set_return_mask_cmd()` 只开启需要的帧（0x01 + 0x03）。

### 3.4 环形缓冲区容量分析

```
缓冲区大小：256 字节
每毫秒数据量（200 Hz，开启姿态+陀螺）：约 28 字节/周期 ÷ 5 ms ≈ 5.6 字节/ms

256 字节可以缓存约 45 ms 的数据。
主循环每 1 ms 取一次 → 缓冲区永远不会满。overrun 应为 0。
```

## 🧩 四、关键代码段详解

### 4.1 位运算取模

```c
#define IMU_RX_BUF_SIZE   256u
#define IMU_RX_BUF_MASK   (IMU_RX_BUF_SIZE - 1u)  // 255

s_rx_head = (uint16_t)((s_rx_head + 1u) & IMU_RX_BUF_MASK);
```

为什么用 `& 255` 而不是 `% 256`？

对于 2 的幂，位运算比除法快得多。当 head = 255 时：
- `(255 + 1) % 256 = 0` ✓
- `(255 + 1) & 255 = 256 & 255 = 0` ✓

结果相同，但位运算更快。

### 4.2 缓冲区空/满判断

```c
// 空：head == tail
if (s_rx_head == s_rx_tail) { 空 }

// 满：(head + 1) == tail
uint16_t next = (s_rx_head + 1u) & MASK;
if (next == s_rx_tail) { 满 }
```

注意：缓冲区"满"的判断是 `head+1 == tail` 而不是 `head == tail`——因为 `head == tail` 已经是"空"了。不用 +1 就无法区分"空"和"满"。

这也意味着缓冲区最多只能用 255 个字节（而不是 256），有一个 slot 永远空着。

### 4.3 批量读取的并发安全性

```c
size_t bsp_imu_uart_rx_pop_bulk(uint8_t *dst, size_t max_len)
{
    size_t got = 0u;
    while (got < max_len) {
        uint16_t h = s_rx_head;
        uint16_t t = s_rx_tail;
        if (h == t) break;
        dst[got++] = s_rx_buf[t];
        s_rx_tail = (uint16_t)((t + 1u) & IMU_RX_BUF_MASK);
    }
    return got;
}
```

这个函数没有关中断！为什么是安全的？

因为只有主循环修改 `tail`，ISR 只修改 `head`。`head` 和 `tail` 是**各自独立的**：
- 主循环读 `head`、写 `tail`
- ISR 写 `head`、读 `tail`

即使 ISR 在循环中途插进来，最多造成"少读 1~2 个字节"——下一拍会补回来。这叫"良性竞态"。

## 🐛 五、常见踩坑

| 现象 | 可能原因 | 解决方法 |
|------|---------|---------|
| MS901M 有数据但 `has_attitude` 永 false | 忘记 `NVIC_EnableIRQ` | 在 init 中添加 `NVIC_EnableIRQ(UART_IMU_INST_INT_IRQN)` |
| ISR 不触发 | 函数名写错 | 确认是 `UART3_IRQHandler`（不是 `UART2_`） |
| overrun 持续增长 | 主循环取数据太慢 | 提高 pop_bulk 频率 / 减小 return mask |
| head 不前进 | 中断没使能或优先级被屏蔽 | 检查 NVIC 和中断优先级配置 |
| 帧解析错乱 | 环形缓冲区数据错位 | 检查 MS901M 波特率是否匹配（115200 8N1） |
