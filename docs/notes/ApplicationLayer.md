# 应用层 (App) 详细解析

应用层是整个项目的“总指挥”。它不需要去管怎么拉高低电平，也不需要自己去写复杂的数学公式，它的任务是**把底层硬件 (BSP) 和中间算法 (Middle) 像搭积木一样拼起来，实现小车真正的行为逻辑**。

本项目的应用层主要包含三个核心模块：安全管家 (`app_safety.c`)、平衡大脑 (`app_balance.c`) 和电机测试 (`app_motor_demo.c`)。

---

## 1. 安全管家 (`app_safety.c`)

这是小车的“保命系统”。平衡车一旦失控，轮子全速旋转会非常危险；同时，锂电池如果过放电会直接报废。因此，在执行平衡控制之前，必须先过安全管家这一关。

### 1.1 状态机设计
安全管家内部维护了一个清晰的状态机，主要有以下几种状态：
- **`DISARMED` (解除武装)**：默认的待机状态，电机不通电。按下板子上的 S1 按键可以切换到 `ARMED`。
- **`ARMED` (武装状态)**：正常工作状态，电机可以自由转动。
- **`FALLEN` (跌倒保护)**：当传感器检测到小车倾角超过了危险值（比如倾斜大于 60 度，说明车已经摔在地上了），安全管家会立刻掐断电机动力，防止车轮在地上疯狂空转。
- **`LOW_BAT_WARN` (低压警告)**：电池快没电了，安全管家会限制电机的最大输出功率（限速），并让红灯闪烁。
- **`LOW_BAT_STOP` (低压急停)**：电池电量达到了危险底线，安全管家会彻底锁死电机（刹车并切断动力），这时候按 S1 也无法启动，必须更换电池。

### 1.2 它是如何介入的？
在平衡大脑计算电机该出多大力的前一刻，会先调用 `app_safety_tick` 函数把当前的角度和电池状态汇报给安全管家。只有安全管家返回 `true`（允许行驶），电机才会被允许转动。

## 2. 平衡大脑 (`app_balance.c`)

这是小车最核心的逻辑文件，负责统筹大局和执行平衡算法。

### 2.1 串级 PID 的组装
在上一节我们讲了 PID 算法，但 `app_balance.c` 里并不是只有一个 PID，而是有两个，并且它们是**串联**起来工作的。这就是 `app_balance_step` 函数在做的事情：

1. **外环：速度环 (`speed_pid`)**
   - 目标：小车当前跑了多快 vs 我希望它跑多快。
   - 工作：它把真实速度和目标速度算个差值，然后用 PID 算出小车**应该倾斜多少度**。
   - 比如：小车走慢了，速度环的计算结果就是“你应该往前倾斜 5 度，借重力加速”。
2. **内环：平衡环 (`balance_pid`)**
   - 目标：小车当前的真实倾斜角度 vs 外环告诉它的目标倾斜角度。
   - 工作：它拿着这两个角度算个差值，用 PID 算出**电机应该出多少 PWM 动力**。
   - 比如：外环让我倾斜 5 度，但我现在是 0 度，平衡环就会算出“电机往前输出 200 的动力”。
3. **转向叠加**
   - 算出了平衡和速度的基础动力后，如果收到左右转向的命令，代码会在左轮动力上减去一个值，在右轮上加上一个值（形成差速），小车就转弯了。

### 2.2 小车的主循环节拍 (`app_balance_run`)
这是整个单片机跑起来后永远不会退出的死循环。它就像一个不知疲倦的时钟，严格按照滴答定时器（SysTick）的心跳来安排工作：

```c
for (;;) {
    if (!bsp_systick_consume_tick()) {
        __WFI(); // 没到 1 毫秒就睡觉，省电
        continue;
    }
    tick_count++; // 每次醒来，时间加 1 毫秒

    // ---- 1 毫秒任务 ----
    // 从串口缓冲区把传感器数据拿出来，喂给状态机解析；更新编码器脉冲。

    // ---- 10 毫秒任务 (100 Hz) ----
    if ((tick_count % 100) == 0) {
        // 读取电池电压
        // 执行上面说的串级 PID 控制 (app_balance_step)
    }

    // ---- 200 毫秒任务 (5 Hz) ----
    if ((tick_count % 200) == 0) {
        // 绿灯闪烁（证明系统没卡死）；红灯显示安全状态（低压/摔倒）
    }

    // ---- 1000 毫秒任务 (1 Hz) ----
    if ((tick_count % 1000) == 0) {
        // 通过串口把各种数据打印到电脑屏幕上，方便我们监控小车状态
    }
}
```
这种设计叫**“时间片轮询”**，它比引入复杂的操作系统（如 FreeRTOS）要轻量得多，对于控制小车平衡来说，它不仅足够了，而且时间非常精准。

## 3. 电机测试模式 (`app_motor_demo.c`)

在刚组装好小车，还没调好平衡参数时，直接让小车自平衡是很危险的（可能会疯跑）。
因此项目中提供了一个演示模式：
- 它可以让你用电脑通过串口发命令（比如发个 `+`），或者按下按键，单独让电机以设定的速度转动。
- 它内部也有一个小小的 PID，用来让左右两个轮子的转速保持一致（因为哪怕发同样的指令，电机制造差异也会导致两边转速不一样）。
- 在 `main.c` 启动时，会先进入这个演示模式，确认硬件一切正常后，按下特定的按键（或者改代码），才会进入真正的 `app_balance_run` 平衡模式。

---

**初学者建议：**
应用层是你以后写代码最常修改的地方。如果你想改变小车的行为，比如加一个超声波避障，你应该在 `app_balance_run` 的时间片里（比如加一个 50 毫秒任务）去读取超声波数据，然后去修改速度环的“目标速度”。
不要去破坏现有的 10ms 控制环和 1ms 数据读取环，它们是小车赖以生存的根基。理解了 `app_balance.c`，你就能随心所欲地控制这台小车了！
